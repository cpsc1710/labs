Part 1 · Core lab

The table and the dice

Each row of the table gives the chances of the next letter. To pick one, lay the row out on a line from 0 to 1, roll a random number r, and take the letter whose segment r lands in. That letter becomes the current letter, and we repeat.

Part 2 · Core lab

Replace the dice with pi

Anthropic describes its watermark as a change to that one step. Instead of a random number generator, the model uses

“the key and a few words that come before to settle what word the model should pick.”Anthropic, How Claude's text watermarking works, August 2026

Pi is a good stand-in for that kind of number source. Its digits look random, but anyone who knows where to read gets the same digits every time. Here are its first digits after the decimal point:

There are two obvious ways to use them. We will try both.

Try 1. Read pi in order

r for letter t = digits 2t−1 and 2t

The first letter uses r = 0.14, the second 0.15, the third 0.92, and so on. Everything else is the same as the dice.

Checking a text

A checker who knows the rule reads pi in order and replays each choice. A ✓ means the letter is the one pi would have chosen.

What goes wrongThe check works only while every letter keeps its original position. Delete one letter and everything after it is compared with the wrong digits, so the ✓ marks after that point are only chance matches.

Try 2. Read pi based on the previous letter

r depends on the letter before

The key is the place in pi where we start reading. After an a we read the two digits at the key; after a b, the next two; after a c, the two after that. Now the checker does not need positions, only the letter before.

What goes wrongWhatever the key, each letter now always leads to the same next letter, so the text falls into a loop within a few steps. With a real model the lookup uses several previous words, so exact repeats are rarer, but the same prompt would still give the same answer every time. The dice gave us variety, and we need to keep it.

Part 3 · Optional

Keep the dice, let pi referee

Explore tournament sampling, step by step. Expand to explore.

Anthropic says Claude's watermark is a version of SynthID-Text, a method published by Google DeepMind. SynthID-Text keeps both sources of numbers. The dice draw several candidate letters from the model's row. The candidates then play a knockout tournament. In each round, pi gives every candidate a coin, 0 or 1, based on the previous letter and the candidate letter. The higher coin wins the match, and a tie is settled by the dice.

Everything that goes into each letter
  • The probability table. The 3 × 3 table from Part 1.
  • The dice. A computer random number generator that gives numbers between 0 and 1. It starts from a fixed seed, 11, so the page opens the same way each time and “Start over” replays the same rolls. Real dice or a different seed would work the same way.
  • The key. A starting position in pi. The default is digit 1.
  • The coin rule. A digit from 5 to 9 gives a 1-coin. A digit from 0 to 4 gives a 0-coin.
  • Which digit each coin uses. Count a = 0, b = 1, c = 2. The coin for a candidate in a given round uses digit number key + 9 × (round − 1) + 3 × (previous letter) + (candidate letter). This is the same as filling the tables row by row.
  • Context. Only the one previous letter. Every text starts with a.
  • Candidates. 8 per letter, each drawn with its own dice roll from the previous letter's row. Repeats are allowed.
  • Matches. Candidate 1 plays 2, 3 plays 4, and so on. Winners keep their order for the next round.
  • Ties. One more dice roll. Below 0.5, the first player wins. Otherwise the second wins.
  • Size. 3 rounds. Anthropic has not published its exact algorithm or settings. This follows the published SynthID-Text design at a very small size.

The key tables

Each round has its own table. Rows are the previous letter and columns are the candidate. The tables are filled with digits of pi in order, starting at the key and going row by row. Round 1 takes the first nine digits, round 2 the next nine, and round 3 the nine after that. Each digit becomes a coin: 5 to 9 gives a 1 and 0 to 4 gives a 0. Shaded cells are 1-coins, and the small number in each cell is the digit it came from.

Example with key 1. Pi starts 3.1415 9265 35… In round 1, row a uses the digits 1, 4, 1, so its coins are 0, 0, 0. Row b uses the next three digits, 5, 9, 2, so its coins are 1, 1, 0.

Where the dice still are. The dice choose the candidates and break ties. Every candidate comes from the model's own row, so the tournament never picks a letter the model would not have considered. Pi only decides which of those candidates wins.

What the key leaves behind. Letters that hold 1-coins win more often than their probability alone would give them. Over many letters, the text holds more 1-coins than text written with plain dice. That surplus is the watermark.

Part 4 · Optional

Checking a text for the watermark

Try a detector, change the key, and edit the text. Expand to explore.

The detector reads the text one letter at a time. Suppose the text has a b followed by an a. To check the a, the detector goes to row b, column a in each of the three key tables and reads the coin there. That gives three coins for this letter.

During writing, letters holding 1-coins won more of their tournaments, so watermarked text collects more 1-coins than ordinary text. The score is the share of all the coins that are 1. The detector needs only the text and the key. It does not run the model or use the probability table.

AssumptionWith only three letters, the score of ordinary text is not exactly 0.5; it depends on the key. So this detector compares a text with 300 ordinary texts of the same length, simulated with plain dice. With a vocabulary of many thousands of tokens, ordinary text averages close to 0.5 for any key.

Things to try

  1. Set the length to 20. The two groups overlap, so a short text cannot be judged.
  2. Give the detector a different key from the writer. The watermarked text then scores like ordinary text.
  3. Press “Change 1 in 4 letters” a few times. Each rewrite weakens the signal, and a full rewrite removes it.
  4. Type your own string of a, b and c, and see whether you can make it look watermarked without the key tables.

Limits Anthropic lists

  • Short passages. Detection does not work well on small samples, as the 20-letter setting above shows.
  • Few real choices. Factual answers and code leave little room to choose. If a row of the table were 1, 0, 0, all eight candidates would be the same letter and the tournament could not leave a mark. Where code must be exact, the watermark is not applied.
  • Light edits by Claude. When Claude only proofreads human writing, the mark can live only in the few corrected words.
  • Rewriting. Light editing probably will not remove it. A complete rewrite where every word is replaced will.
  • What a positive result means. It says Claude was likely involved, not that Claude wrote the text. Claude may have translated, summarized or edited it. The mark carries no information about the user, organization or conversation.
  • What a negative result means. It does not show a person wrote the text. Other AI systems use different keys or none, and older Claude models were still being covered during a transition period.
